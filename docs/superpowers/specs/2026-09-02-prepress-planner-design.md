# «Препресс-Планер» — Design / Спецификация (утверждено)

> Версия: 0.3 (утверждена) · Дата: 2026-09-02
> Платформы: iOS · Windows · macOS · Linux
> Стек: Flutter/Dart (домен — чистый Dart, отдельный пакет) + Python-сервисы
> Монетизация: подписка с пробным периодом 15 дней, собственный лицензионный сервер

## 1. Парадигма и назначение

Приложение — **препресс-планировщик расходных материалов и экономико-технического обоснования (ТЭО)** тиражей этикеток (контекст: производство гибких высечных штампов / ротационная высечка). Отвечает на вопросы:

1. Сколько материала (полотно/субстрат) уйдёт на тираж с учётом **формы и размера этикетки** (чистая площадь контура, не только W×H), зазоров, шестерни (Z/CP), ширины цилиндра/полотна; режимы «по количеству N» и «по длине L».
2. Какой раскрой оптимален: перебор ориентации 0°/90°, рядов (шов обязан сходиться: `step_y = rapport/r`), колонок; критерий — минимум расхода и стоимости на этикетку.
3. Сколько это стоит (ТЭО): сортамент материала (₽/м²), машиночасы (ставка ₽/ч), рабочая скорость печати, время переналадки, рабочее время смены, оснастка, наценки → себестоимость 1000 шт, экономия вариантов, точка безубыточности, загрузка смены, чувствительность.
4. Диагностика и подготовка входной геометрии заказчика: выявление ошибок (разрывы, пересечения, дубликаты, пыль, острые углы, малые зазоры), лечение, топология, распознавание/генерация массивов.

**Удалено (не переносится):** УФ-маска, генерация УП/G-кода, калибровка ЧПУ, техкарта ЧПУ, режимы фрезы, время фрезеровки.

**Пользователь:** технолог/экономист/менеджер тиражей. Русскоязычный UI. Локальная работа; сеть — только конвертация закрытых форматов и лицензии.

## 2. Решения

| Вопрос | Решение |
|---|---|
| Стек | Flutter + Dart: iOS, Windows, macOS, Linux одним кодом; домен — чистый Dart |
| Закрытые форматы (AI/CDR/EPS) | Серверная конвертация → SVG/PDF (FastAPI + Inkscape/Ghostscript, переиспользуются парсеры `cam_pipeline`) |
| Монетизация | Свой лицензионный сервер; **триал 15 дней** с первой активации; подписка Pro (месяц/год); iOS — StoreKit IAP + проверка Apple-ресивера; десктоп/Linux — ключ-активация по machine-id, офлайн-грэйс 30 дней |
| Android | вне scope |
| Домен | расчёт расхода + ТЭО; геометрия — входная стадия |
| Название | «Препресс-Планер» (рабочее, сменное) |

## 5. Доменная модель

- `CamPath { points: List<(x,y)>, isClosed, layerName }` — полилиния, мм, кривые дискретизированы (шаг 0.05), координаты окр. 0.0001.
- `LayoutParams`: label_w/h, gap_x/y, z_teeth, cp, rapport_manual, cyl_width, web_width, undercut, mode('count'|'length'), count, length, min_gap.
- `ManufacturingParams`: tolerance=2.0, min_loop_area=1.0, min_radius=0.2, min_gap=0.5.
- `Issue { kind, severity(error|warning|suggestion), points, message, suggestion, fixable, index }`.
- `AppState`: layout, manuf, geometry, healedGeometry, issues, calc, variants, selectedVariant, scene, inputFile, projectName.
- Экономика: `AssortmentItem {id, name, pricePerM2, minOrderM2?}`, `Machine {id, name, ratePerHour, speedMetersPerMin?, labelsPerHour?, setupTimeHours}`, `WorkTime {hoursPerShift=8, shiftsPerDay=1}`, `OrderEconomics {...}`.

## 6. Математика расхода (порт 1:1 + shape)

```
rapport = Z·CP (или ручной); d_pitch = rapport/π; d_cyl = d_pitch − 2·undercut
rows r: step_y = rapport/r, gap_y_act = step_y − H ≥ min_gap
cols: cols·W + (cols−1)·gap_x ≤ min(цилиндр, полотно)
count: revs = ceil(N/per_rev), L = revs·rapport | length: revs = floor(L/rapport)
area = L·web_width (м²); S_used = N·S(форма); waste = area − S_used; waste% = waste/area·100
расход на шт = area / N_total
```

Форма этикетки: из геометрии (полигон мастера) или пресеты (прямоугольник, скруглённый R, круг, эллипс, контур): bbox W×H, чистая площадь S, efficiency = S/(W·H).

**Эталон (обязателен):** прямоугольник 50×30, зазоры 3, Z=96, CP=3.175, cyl=web=300, N=5000 → rapport=304.8, rows=9, cols=5, revs=112, N_total=5040, длина=34137.6 мм, used_width=262.0, отходы=26.18%, per_label=2032.0 мм²/шт, excess=40. Прямоугольник: результаты идентичны Python.

## 7. Экономика / ТЭО

**Статьи затрат (редактируемые каталоги, JSON):**
1. Сортамент — каталог субстратов (наименование, цена ₽/м², мин. заказ).
2. Машины — название, ставка машино-часа ₽/ч, рабочая скорость печати (м/мин или этикеток/ч), время переналадки (ч/заказ).
3. Рабочее время — часов в смену, смен в день.
4. Оснастка/штамп — ₽/заказ (опц.). 5. Наценки — % (опц.).

**Расчёт на вариант:**

```
run_time_h   = L / (speed_m_per_min·60) | N / labels_per_hour
total_time_h = setup + run_time_h
machine_cost = total_time_h · rate ₽/ч
C_material   = area_m2 · pricePerM2(сортамент)
C_total      = C_material + machine_cost + C_tool + наценки
C_per_1k     = C_total / N · 1000
загрузка     = total_time_h / (hours_per_shift·shifts)  (>100% → предупреждение)
этикеток/ч, шт/смену
```

**Выводы:** таблица вариантов (расход м², отходы %, C_total, C_per_1k, машинное время; сортировка по C_per_1k); экономия лучшего против базового (₽/%); сравнение count|length; break-even по тиражу при разной оснастке (`N* = ΔC_tool/(ΔC_per_1k/1000)`); чувствительность (цена м², ширина полотна, ставка, скорость — интерактивный пересчёт).

**Отчёты:** PDF ТЭО (шапка, параметры, эскиз, таблица расхода, блок «Производство»: машина/скорость/переналадка/маш. время/₽/загрузка, экономика, дата); XLSX (листы «Расчёт», «Варианты», «ТЭО»); DXF мастера и раскроя.

## 8. Монетизация (триал 15 дней)

- **Триал 15 дней** с первой активации (machine-id на десктопе; iOS — StoreKit introductory offer 15 дней). Сервер хранит дату старта, защита от сброса переустановкой.
- **Free** после триала: 1 проект, прямоугольный расчёт, без экспорта/ТЭО. **Pro** (месяц/год): всё.
- UI: экран «Пробный период: осталось N дней», paywall, `FeatureGate`.
- API: `POST /license/activate` (старт триала/ключ), `POST /license/validate`, `GET /license/entitlements`, `POST /webhooks/stripe|apple`. Офлайн-грэйс 30 дней (кэш токена).

## 9. Ограничения окружения разработки

- Исходящий HTTPS для процессов заблокирован; работает только plain HTTP → SDK Dart ставится по http, **сторонние pub-пакеты недоступны**: весь домен — только стандартная библиотека Dart. Отчёты XLSX — «store»-zip + XML (своя реализация), PDF — своя генерация. PDF-парсинг: если поток FlateDecode — своя реализация inflate или серверный фолбэк (решение фиксирует агент A2).
- Сборка iOS/нотаризация — на CI/macOS позже (Ф5).

## 10. Критерии приёмки

1. Запуск и сквозной сценарий на iOS/Windows/macOS/Linux; импорт DXF/SVG/PDF локально, AI/CDR/EPS через сервер.
2. Эталонная математика 1:1 (см. §6).
3. Shape-расход по чистой площади; оптимизация 0°/90° с efficiency.
4. ТЭО: сортамент, машиночасы, скорость, переналадка, рабочее время, оснастка; C_per_1k, экономия, break-even, загрузка смены, чувствительность.
5. PDF ТЭО и XLSX формируются; DXF открываются.
6. В `packages/core` нет модулей маски/G-кода (grep mask|gcode|уф|уп = 0).
7. Триал 15 дней + гейтинг Free/Pro на всех платформах; iOS — IAP.
8. `dart test` (домен) и `pytest` (сервисы) зелёные; CI (GitHub Actions).

## 12. Риски

1. Булевы операции в Dart → fuzz vs Shapely; запасной путь Rust-ядро.
2. PDF-парсер в Dart → inflate своими силами или серверный фолбэк.
3. App Store: триал/подписка только через IAP.
4. Нет доступа к pub.dev → только stdlib (учтено в §9).
5. Объём → изолированные фазы, контрольные точки после каждой.
