## 1. Назначение и принципы

Документ фиксирует единый визуальный язык и правила интерфейса, чтобы правки в разных экранах не расходились: одинаковые подписи, отступы, цвета статусов, форматы чисел и поведение при ошибках.

Принципы:

1. **Русскоязычный интерфейс.** Все подписи, кнопки, статусы и ошибки — по-русски (`docs/HANDOFF.md:274` — «тексты ошибок/UI/коммиты — русские»).
2. **Понятность инженеру-препрессору.** Каждый параметр сопровождается пояснением; подписи содержат единицы измерения («Зазор X, мм», «Цена, ₽/м²») — `app/lib/src/widgets/params_form.dart:73-124`, `app/lib/src/screens/teo_screen.dart:504`.
3. **Плотная инженерная вёрстка.** Много параметров на экране, компактные поля (`isDense: true`), сетки `Wrap`, таблицы с горизонтальной прокруткой — `params_form.dart:88-124`, `variants_table.dart:25-27`.
4. **Предсказуемость.** Одно действие — одно место: «Рассчитать» в раскрое (`params_form.dart:147-149`), «Применить» для варианта (`layout_screen.dart:247-253`), «Оформить Pro» в paywall (`paywall_screen.dart:71-77`).
5. **Доступность.** Копируемый журнал событий, подсказки (Tooltip) на параметрах, единый источник ошибок — см. §5.

## 4. Паттерны

### 4.1 Пошаговые длительные операции

Фактическая цепочка статусов (все — в текстовом состоянии экрана, `setState`):

- Импорт локального файла: «Чтение файла…» (`geometry_screen.dart:571`) → «Разбор файла…» (`:591`) → «Анализ технологичности…» (`:683`) → итог «Загружено контуров: N; ошибок: M.» (`:706-708`).
- Импорт закрытого формата: «Конвертация закрытого формата на сервере…» (`:608`) → «Разбор сконвертированного SVG…» (`:621`) → «Конвертация успешна. …» (`:623`).
- Распознавание массива: «Распознавание массива…» (`:960`) → «Лечение мастер-элемента…» (`:980`) → «Анализ мастер-элемента…` (`:1002`) → «Размножение по закону…» (`:1008`) → итог с размерами этикетки и шага (`:1069-1073`).
- Лечение: «Лечение геометрии…» (`:816`) → «Вылечено: N контуров.» (`:838`).
- Экспорт: «Формирование PDF…» (`reports_screen.dart:185`), «Формирование XLSX…» (`:214`), «Формирование DXF…» (`:238`) → путь/имя файла.

**[канон]** Любая операция длиннее «мгновенной» обязана: (1) выставить `_busy = true`, (2) показать `LinearProgressIndicator`, (3) писать этап в статус, (4) записывать начало/итог в журнал (`AppLog`), (5) в `finally` снять `_busy`. Пример-эталон — `geometry_screen.dart:587-601`.

## 9. Как применять: чек-лист для новой фичи

1. **Токены.** Ни одного литерала цвета/отступа/ширины: цвета — из `colorScheme` (или токенов), отступы — из шкалы 4/6/8/12/16/24, ширина поля — из набора 120/140/170/240.
2. **Текст.** Все подписи по-русски, с единицами измерения («Зазор X, мм», «Цена, ₽/м²»); англицизмов нет.
3. **Tooltip.** У каждого параметра и у каждого действия с неочевидным эффектом — Tooltip с пояснением смысла и формулы.
4. **Действия.** Одно главное залитое действие (`FilledButton`/`FilledButton.icon`) на блок; второстепенные — `OutlinedButton`/`TextButton`; деструктивные — с фоном `colorScheme.error`.
5. **Длительная операция.** `_busy` + `LinearProgressIndicator` + статус этапа («Разбор файла…» → «Анализ…» → итог) + запись начала и итога в `AppLog`; снятие `_busy` в `finally`.
6. **Таймаут.** У каждой внешней/тяжёлой операции — таймаут и понятная ошибка с числом секунд и советом (образец — `geometry_screen.dart:84-87`).
7. **Ошибка.** Формат «что случилось + что делать»; показать в статусе, записать в журнал с `LogLevel.error`; цвет — `colorScheme.error`.
8. **Пустое состояние.** Констатация + что сделать; для отсутствующего проекта — «Создайте или откройте проект на вкладке «Проекты».».
9. **Числа.** Деньги — 2 знака; метры — 3; отходы — 2; площадь на этикетку — 6; машинное время — 4; координаты — 4; единицы — в подписи, не в значении.
10. **Доступность.** Иконочная кнопка — с `tooltip`; кегль ≥ 12; смысл не только цветом (дублировать текстом или иконкой); диагностический текст — копируемый (`SelectableText`/`SelectionArea`).
11. **Адаптивность.** Проверить обе ветки: ширина > 700 px (`NavigationRail`, `home_shell.dart:146`) и ≤ 700 px (`NavigationBar`); фиксированные ширины полей — из токенов, длинные подписи — `TextOverflow.ellipsis`.
12. **Отчёты.** Если фича попадает в PDF: кегль из шкалы 7–14 pt, отступы 45 pt, линии 0.4/0.6/0.7/1.0, подписи — вне рамки эскиза, линия не пересекает текст.
13. **Документ.** Если правило вводится впервые — записать его в этот файл (со ссылкой `файл:строка`), а не только в комментарий кода.
