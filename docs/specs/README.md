## 1. Назначение набора

`docs/specs/` — **актуальное инженерное описание системы**, пригодное для
входа в проект с нуля: как устроен репозиторий, из чего состоит домен, какие
форматы данных ходят внутри и на границах системы.

Набор отличается от остальной документации проекта двумя свойствами:

| Свойство | Что это значит |
|---|---|
| **Проверяемость** | Каждое утверждение имеет адрес в коде (`файл:строка`), а не является пересказом намерений |
| **Актуальность** | Описывается текущий код на HEAD, а не исторический контракт; расхождения с историей помечаются явно |

Набор **не заменяет** и **не дублирует**:

- `agents/00..14.md` — исторические контракты субагентов, по которым строился
  MVP; они намеренно не переписываются под код (`agents/README.md:1-8`);
  ссылки на них в наборе даются как на **историю**;
- `docs/HANDOFF.md` — снимок контекста передачи проекта;
- `docs/VERIFICATION.md` — факты приёмки (прогоны, числа);
- `SECURITY.md` — аудит безопасности и план устранения;
- `README.md`, `РУКОВОДСТВО_ПОЛЬЗОВАТЕЛЯ.md` — обзор и пользовательская часть.

Кратко; развёрнуто — в `00_architecture.md`, §6.

## 4. Правило ведения набора

Набор обновляется **в том же коммите**, что и изменение, которое делает его
неверным. Практическое правило: если правка меняет одно из перечисленного —
соответствующий файл набора обязателен к обновлению.

| Что изменилось в коде | Что обновлять |
|---|---|
| Публичная функция/класс в `packages/core/lib/**` | `01_domain_core.md` (раздел модуля) |
| Поля JSON, сохраняемого на диск (`project.dart`, `material_library.dart`, `entitlement_store.dart`, `account_client.dart`) | `02_data_formats.md` |
| Имена/формат экспортируемых отчётов | `02_data_formats.md`, §7 |
| Структура каталогов, новый слой, новый сервис | `00_architecture.md` |
| Изменение схемы данных без обратной совместимости | `02_data_formats.md`, §9 + `00_architecture.md`, §7 |
| Новый файл набора | `README.md`, §2 |

Дополнительные требования:

1. **Шапка.** Каждый файл начинается строкой
   `Статус: актуален на <дата> (HEAD <короткий SHA>)`. При обновлении файла
   шапка обновляется вместе с ним.
2. **Ссылки.** Техническое утверждение — со ссылкой `путь/файл:строка`.
   Диапазон строк — для блока, одна строка — для конкретного объявления.
   При расхождении кода и документа прав **код**.
3. **Отсутствие.** Если факт не найден в коде, пишется «в коде не найдено» —
   без предположений.
4. **История.** Контракты `agents/00..14.md` не переписываются; расхождения
   фиксируются в наборе ссылкой на конкретное место контракта.
5. **Язык.** Русский; технические идентификаторы (`schemaVersion`,
   `parseBytes`, `HEALED_POLY`) — как в коде.

## 6. Как читать ссылки на код в наборе

Ссылки даются относительно корня репозитория, например:

- `packages/core/lib/src/calculator/material.dart:158` — сигнатура
  `computeMaterial`;
- `packages/core/lib/src/model/params.dart:18-33` — конструктор
  `LayoutParams` с эталонными дефолтами;
- `app/lib/src/projects/project.dart:102-116` — `Project.toJson()`
  (`schemaVersion: 2`);
- `deploy/nginx/pp-web.conf:31-38` — проксирование `/auth` и `/payments`.

Строки указаны по состоянию на HEAD `bed533e`. После правок нумерация может
сдвинуться — при расхождении ориентируйтесь на имена символов, они стабильнее.

## 7. Быстрая проверка актуальности набора

Команды не запускались в рамках составления набора (работа велась только
чтением); они приведены как способ перепроверки на новом месте —
полный перечень в `docs/VERIFICATION.md:102-130`.

```powershell
# 1. Актуальный HEAD (сверьте с шапками файлов набора)
git -C "<корень>" log -1 --format="%H %s"

# 2. Проверка, что набор описывает существующее дерево
git -C "<корень>" ls-files docs/specs

# 3. Эталонные числа домена (эталон 50×30 → 9×5, 5040 шт)
& '<корень>\.tools\dart-sdk\bin\dart.exe' tool/e2e.dart   # из packages/core

# 4. Тесты домена (16 файлов-скриптов)
powershell -File scripts/run_domain_tests.ps1
```

Расхождение шапки набора с выводом команды 1 — признак, что файл набора
нужно обновить (см. §4).
