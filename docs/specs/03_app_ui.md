Документ описывает карту экранов Flutter-приложения (`app/lib`), точные подписи элементов, состояния экранов, пользовательские потоки, гейтинг Free/Pro, различия web/desktop/мобильных и известные дефекты. Каждое утверждение — со ссылкой на код.

Пакет приложения — `prepress_planner` версии `1.0.0+1` (`app/pubspec.yaml:5`), зависимость домена
`prepress_core` по path (`app/pubspec.yaml:25-26`). Для мобильных сборок добавлены внешние
pub.dev-плагины `file_selector: ^1.1.0` и `path_provider: ^2.1.6` + пин `path_provider_foundation: 2.5.1`
(`app/pubspec.yaml:14-24`); ранее внешних зависимостей не было.

**Каталоги данных на мобильных.** `main()` асинхронный: сначала вызывается `mobileDataDir()`
(`app/lib/main.dart:13-25`), и результат передаётся в `PrepressPlannerApp({this.dataDir})`
(`main.dart:27-32`). Внутри `_stateDir`/`_projectsDir` равны `state`/`projects` при `dataDir == null`
(desktop/web) и `$dataDir/state`, `$dataDir/projects` — на Android/iOS (`main.dart:44-49`); эти каталоги
получают `EntitlementStore`, `LicenseController(stateDir:)`, `MaterialLibrary` и `ProjectStore`
(`main.dart:54-60, 78-79`). Сам каталог — `getApplicationDocumentsDirectory()/PrepressPlanner`
(`app/lib/platform/app_dirs_io.dart:11-31`); на web/desktop функция возвращает `null`
(`app_dirs_web.dart:5-7`). Подробности путей — `docs/specs/05_platforms_builds.md` §12.

## 6. Пользовательские потоки

1. **Создание проекта.** «Проекты» → «Имя проекта» → «Создать»
   (`projects_screen.dart:42-55`). Без Pro-доступа и при непустом списке — шторка
   «Второй проект доступен в Pro (Free — 1 проект)» (`45-50`). Далее `save` +
   `load` + `onOpen` → переключение на «Геометрию» (`home_shell.dart:50-55`).
2. **Импорт.** Desktop — путь в поле или «Обзор» → «Импорт» (`geometry_screen.dart:225-238`);
   web — «Импорт файла» (браузерный диалог, `562-566`); мобильные — «Импорт файла»
   (системный picker, `554-570`, `platform/files_io.dart:84-93`). `.ai/.cdr/.eps` уходят на
   сервер конвертации (`583`), остальные форматы разбираются локально.
3. **Лечение.** «Вылечить всё» → `healGeometry` → повторный анализ технологичности,
   список ошибок обновляется (`816-859`).
4. **Массив.** «Распознать массив»: мастер вылечивается отдельно, помечается слоем
   `MASTER`, размножается на слой `ARRAY`, параметры раскроя заполняются
   автоматически (`956-1102`, особенно `1030-1046`). Нет файла — «Сначала
   импортируйте векторный файл.» (`962`); массив не найден — «Массив не найден.
   Совет: выполните «Вылечить всё» и повторите…» (`979-981`).
5. **Ширина материала.** Блок «Ширина материала» (после распознавания): поля
   слева/справа/сдвиг → «Применить к раскрою (полотно)» пишет `webWidth` (`358-461`).
6. **Раскрой.** Правка параметров → «Рассчитать» (`layout_screen.dart:152-187`).
7. **Варианты.** «Перебрать варианты» (Pro) → выбор строки → «Применить»: вариант
   становится `calc`, номер — в `selectedVariantIndex` (`189-283`). Альтернатива —
   «Рассчитать рейтинг» по Z и клик по строке (`297-373`).
8. **ТЭО.** «Сортамент»: выбрать `(пример)`-материал или «Добавить материал» →
   «Новый материал» → «Создать» (`teo_screen.dart:468-561`; материал сразу
   становится выбранным, `material_library.dart:84-111`). Заполнить «Машина»,
   «Оснастка, ₽», «Наценка, %», «Приладка: материал, м», «Смена, ч», «Смен в
   сутки», «Цена смены, ₽» → «Рассчитать ТЭО» → «Чувствительность» → «Пересчитать».
9. **Отчёты.** «PDF ТЭО» / «XLSX» / «DXF мастера». Desktop пишет в каталог
   `projects` (`reports_screen.dart:111-112`, `platform/save_out_io.dart:11-23`),
   web скачивает (`platform/save_out_web.dart:8-9`, `platform/files_web.dart:50-62`),
   мобильные — в `<каталог приложения>/PrepressPlanner/reports` (`platform/save_out_io.dart:13-15`);
   в файловом менеджере устройства эти файлы не видны (`docs/specs/05_platforms_builds.md` §12).

## 11. Ограничения и известные дефекты

1. **Подпись «двойной клик — открыть», а работает один клик.** Текст подсказки в
   списке проектов `projects_screen.dart:91`, обработчик — одиночный `onTap`
   (`projects_screen.dart:93-96`).
2. **Проекты нельзя удалить/переименовать.** `ProjectStore` умеет только
   `save/load/listNames` (`project.dart:305-316`); UI-кнопок удаления нет.
3. **Одинаковое имя проекта перезаписывает файл.** Имя санитизируется и служит
   именем файла (`project.dart:300-303, 305-307`); проверки существования нет.
4. **ТЭО-параметры не персистентны.** Машина, оснастка, наценка, приладка, смена,
   цена смены и результат ТЭО живут только в состоянии экрана (`teo_screen.dart:56-73`)
   и не попадают в `Project` (`project.dart:66-79`) — после перезапуска сбрасываются.
5. **Отчёты не используют параметры ТЭО пользователя.** PDF/XLSX строятся с машиной
   `PriceCatalog.defaults().machines.first`, рабочим временем и валютой из каталога
   (`reports_screen.dart:46, 64-66`); из пользовательских данных учитывается только
   выбранный материал (`reports_screen.dart:29-37, 208-210`). Результат
   «Чувствительности» в отчёты не попадает (`teo_screen.dart:351, 432-457`).
6. **«DXF мастера» требует `healedPaths`, а не слоя MASTER.** Если массив распознан
   без предварительного «Вылечить всё», `healedPaths` пуст и кнопка неактивна
   (`reports_screen.dart:185-187`, `geometry_screen.dart:1069`), хотя мастер есть в
   `pattern.masterPaths` (`geometry_screen.dart:1048-1062`).
7. **Комментарий про «кнопку-шестерёнку» адреса конвертера расходится с кодом:**
   адрес в UI не редактируется, есть только «Запустить сервер» / «Проверить сервер»
   (`geometry_screen.dart:125` против `739-767`); на мобильных вторая ветка всегда
   «Проверить сервер» (`:769-773`).
8. **Экран «Проекты» не пишет в журнал и не имеет плейсхолдера** для пустого списка
   (только заголовок и поле ввода) — `projects_screen.dart:59-99`.
9. **ТЭО не пишет в журнал** (файл не использует `AppLog`); операции с материалами
   подтверждаются только `SnackBar` (`teo_screen.dart:459-464`).
10. **Раскрой: вариант визуально выделяется, но в расчёт попадает только после
    «Применить»** — это осознанное поведение, но пользователю нужно нажать кнопку
    (`layout_screen.dart:47-49, 224-257`).
11. **Пустой список Z молча ничего не делает в UI** — только запись в журнал
    (`layout_screen.dart:299-302`).
12. **Квота Free считается по числу уже сохранённых проектов, а не по аккаунту**
    (`projects_screen.dart:45-50`) — это локальная защита, обходится удалением или
    переименованием файлов проекта. Гейтинг вообще клиентский: `entitlement.json` —
    обычный редактируемый файл (`entitlement_store.dart:15-17`; см. `SECURITY.md`,
    раздел 2, «Лицензирование — клиентская заглушка»).
13. **На мобильных данные и отчёты недоступны пользователю извне.** Проекты, состояние и
    отчёты лежат в песочнице приложения (`platform/app_dirs_io.dart:11-40`); отчёты не попадают
    в «Загрузки», нет кнопки «поделиться» и нет выбора внешнего каталога. В UI это отражено
    подписью «Экспорт: файлы сохраняются в каталог приложения (подкаталог reports)»
    (`reports_screen.dart:158-163`).
14. **Локальный конвертер на мобильных недоступен.** Кнопка всегда работает как «Проверить сервер»
    (`geometry_screen.dart:769-773`), поэтому AI/CDR/EPS на телефоне возможны только при
    доступном сервере конвертации.
15. **Мобильные сборки не проверялись на реальном устройстве.** В этой сессии не выполнялись
    ни сборка APK, ни запуск на устройстве/эмуляторе, ни запуск iOS-сборки (только macOS) —
    поведение системного picker'а, песочницы и сетевых запросов **требует проверки**; см.
    `docs/specs/05_platforms_builds.md` §7, §8, §15.
16. **Экран «Проекты»/списки на узком экране.** Навигация переключается на `NavigationBar` при
    `maxWidth <= 700` (`home_shell.dart:146-147`), что как раз покрывает телефонную ширину, но
    отдельной мобильной вёрстки (крупные кнопки, отступы под жест-бар) в коде нет —
    удобство работы на телефоне **требует проверки**.
