## Экраны (вкладки по сценарию)
1. **Проекты** — список/создание/открытие (project_state.json v2), имя проекта.
2. **Геометрия** — импорт («Обзор…» — встроенный диалог выбора файла, path-ввод тоже есть; локально DXF/SVG/PDF, AI/CDR/EPS — через services/converter), список ошибок (`Issue`) + маркеры на холсте, кнопки «Вылечить всё»/«Исправить», «Распознать массив» (см. ниже) и «Сгенерировать сетку».
3. **Расход/Раскрой** — форма LayoutParams, результат расхода, таблица вариантов (выбор), превью раскроя.
4. **Экономика/ТЭО** — редактор каталога (сортамент/машины/рабочее время), таблица ТЭО по вариантам, слайдеры чувствительности, выбор лучшего.
5. **Отчёты** — кнопки экспорта PDF/XLSX/DXF, сообщение о результате.

## Canvas (порт CanvasManager)
Сцены `geometry` (полилинии + маркеры ошибок цветом: красный/оранжевый/пурпурный/жёлтый) и `layout` (полотно + сетка этикеток + размеры). Зум колесом/пинчем, пан, линейки, fit-to-screen, замер. CustomPainter, трансформация мировых координат.

## Состояние
`AppState` (в core: model), UI-репозиторий проекта: загрузка/сохранение JSON v2 (версия схемы, миграции). Тяжёлые операции (парсинг, лечение, генерация) — в Isolate (`compute`/`Isolate.run`) с прогресс-баром; UI не блокируется. Локальные операции имеют **таймаут 90 с** (зависший/гигантский файл → понятная ошибка вместо бесконечного спиннера); статусы поэтапные: «Разбор файла…» → «Анализ технологичности…». Все post-await `setState` защищены `if (mounted)` (переключение вкладок во время расчёта не роняет экран).

## «Распознать массив» (реализовано 2026-09-03)
Работает по вылеченным контурам, а при их отсутствии — по исходным. Шаги со статусами: распознавание → лечение мастер-элемента (слой `MASTER`) → анализ ошибок по мастеру → размножение по закону на слой `ARRAY` → автозаполнение параметров раскроя (этикетка и зазоры из файла) → статус с размерами. Холст раскрашивает слои: MASTER — бирюзовый, ARRAY — индиго, HEALED_* — тёмный, исходные — серый. Новый импорт сбрасывает healed/pattern/array (старое лечение файла недействительно).

## Журнал событий (реализовано 2026-09-03)
Единое окно «Журнал событий» (иконка в шапке приложения на любой вкладке) для просмотра и **копирования ошибок** — не нужно ловить их из консоли:
- `app/lib/src/logs/app_log.dart` — синглтон `AppLog extends ChangeNotifier` (`AppLog.instance`): лента `LogEntry{time, level, source, message}` (I/W/E), лимит 2000 записей, `record(source, message, {level})`, `fullText` для копирования, `clear()`, счётчик `errorCount` (бейдж на кнопке). Записей нет на диске — только память сессии.
- Глобальный перехват в `main()`: `AppLog.instance.installGlobalHandlers()` вешает `FlutterError.onError` и `PlatformDispatcher.onError` (стек ужимается до 40 строк) — необработанные падения тоже видны и копируются.
- `app/lib/src/widgets/log_window.dart` — `showLogWindow(context)`: список свежих записей сверху, строки `SelectableText` внутри `SelectionArea` (выделение мышью), кнопки «Копировать всё (N)» (Clipboard), «Очистить», «Закрыть»; цвет по уровню (ошибка — красным).
- Источники записей: экраны Геометрия/Отчёты логируют этапы и все ошибки (те же сообщения, что в статус-строке, плюс таймстемп); сетевые/серверные ошибки конвертера приходят через перехват исключений в экране импорта.
