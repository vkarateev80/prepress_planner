## 2. Высоко

- **Конвертер публичный, без авторизации, без лимитов** (`services/converter`): безлимитный параллелизм (поток на запрос), у Ghostscript/Inkscape нет timeout/лимитов памяти, размер проверяется после полной записи, magic-байты не проверяются; статика `/data` отдаёт `work/` с копией исходника и `jobs/*.json`; всё от **root** в контейнере. (Хорошее: `-dSAFER` у GS, без `shell=True`.)
- **Все 4 контейнера от root**; base-образы и apt-версии не зафиксированы (нерепроизводимо).
- **Лицензирование — клиентская заглушка**: Pro гейтится редактируемым `state/entitlement.json`; license-сервер не развёрнут и клиентом не вызывается; серверного энфорсмента нет.
- **Токен сессии открытым текстом** на клиенте (`state/session.json`, localStorage в web); живёт 30 дней.
- **Хост**: `/stack`, `/stack/deploy`, `/stack/deploy/web` — 777; `.env` — 644 (мир-читаемый); пользователей кроме root нет; **317 необновлённых пакетов ОС**, ядро 2022 г.

## 3. Средне / низко (кратко)

- `/docs` и `/openapi.json` открыты наружу на всех сервисах.
- Перечисление email (register→409, reset→404, `dev_hint`); регистрация без подтверждения email.
- Локальный конвертер desktop — без токена/Host-проверки; `0.0.0.0` считается «локальным».
- auth.db создаётся от root (0644); reset-коды в БД — sha256 без соли.
- `machine_id` на слабом ГПСЧ (`_Random`).
- Осиротевший license-сервис (не развёрнут): маршруты `/admin/keys` и вебхуки без auth/подписи, дефолтный секрет — публичная константа `dev-secret-change-me`.
- TTL сессий 30 дней без чистки; тексты исключений конвертера утекают клиенту; версии зависимостей не закреплены; `pytest`/`httpx` в прод-requirements.

## 4. Что в порядке

- Пароли: PBKDF2-SHA256 (200 000 итераций, соль, constant-time сравнение).
- Токены сессий opaque (256 бит), в БД только sha256; реальный отзыв; лимит устройств 1/1.
- SQL-инъекций нет; `shell=True`/`os.system` нет; path traversal и SSRF не найдены.
- XSS-поверхность клиента минимальна; web ходит единым origin через nginx; CORS выключен.
- Пароли не логируются; история git чистая (реальных секретов никогда не коммитилось).
- `PP_AUTH_SECRET` на сервере — 64 hex-символа; в репозитории — только `.env.example`.

## 5. План устранения

**Фаза 1 — срочно (остановить активные атаки):**
1. Код-фикс auth: не возвращать код сброса в ответе вне явного dev-флага (при отсутствии SMTP — 503); лимит попыток reset-кода + код ≥8 символов; `docs_url=None` в проде.
2. SSH: смена пароля root, `PasswordAuthentication no`, `PermitRootLogin prohibit-password` (доступ только по ключу `pp_vps_ed25519`), установка fail2ban.
3. ufw: открыть только 22 и 8081 — после перевода десктопа на единый origin :8081 (nginx уже проксирует `/auth`, `/payments`, `/convert`, `/data`).
4. Права: каталоги 755, `.env` 600; контейнеры — не-root + лимиты; apt-апгрейд ОС.
5. Десктоп-сборки: дефолтные URL → `http://193.233.193.12:8081`.

**Фаза 2 — после появления данных заказчика:**
6. SMTP для forgot (или явное отключение сброса); у заказчика почты и домена нет.
7. Домен + HTTPS (Let's Encrypt) для web и API.
8. Реальная платёжная интеграция (сейчас заглушка); подпись вебхуков.
9. Решение судьбы license-сервиса; серверный энфорсмент Pro.
10. Пиннинг зависимостей, не-root в Docker, ограничения конвертера (лимиты/таймауты/auth).
